How AES Work

ดูตารางข้อมูลขนาด 4×4 ไบต์ เดินทางผ่าน SubBytes, ShiftRows, MixColumns และ AddRoundKey ทีละขั้นตอน จากนั้นดูว่าทำไมรหัสที่มีจำนวนรอบน้อยเกินไปถึงเผยกุญแจออกมาได้ง่ายๆ

ปูพื้นฐานก่อนเริ่ม: 4 ขั้นตอนใน 1 รอบของ AES

ข้อมูลขนาด 128 บิต (16 ไบต์) จะถูกจัดเรียงเป็นตารางขนาด 4×4 ไบต์ก่อน แล้วใน "1 รอบ" ข้อมูลทั้งตารางจะถูกจับไปแปลงรูปแบบด้วย 4 ขั้นตอนทางคณิตศาสตร์เรียงกันแบบนี้:

ขั้นที่ 1

SubBytes
(การแทนที่)

เปลี่ยนทุกไบต์ในตารางด้วยไบต์อื่นตามตารางอ้างอิงที่ตายตัว (เรียกว่า S-box)

เหมือนตารางโค้ดลับ: เอาไบต์เดิมไปเปิดตาราง แล้วได้ไบต์ใหม่มาแทนที่ ทำแบบนี้ทีละไบต์จนครบทั้ง 16 ไบต์
ขั้นที่ 2

ShiftRows
(การสลับแถว)

เลื่อนไบต์ในแต่ละแถวของตารางไปทางซ้าย ด้วยระยะทางที่ไม่เท่ากัน

แถวที่ 1 ไม่ขยับ, แถวที่ 2 เลื่อน 1 ช่อง, แถวที่ 3 เลื่อน 2 ช่อง, แถวที่ 4 เลื่อน 3 ช่อง (วนกลับมาต้นแถวเมื่อสุดขอบ)
ขั้นที่ 3

MixColumns
(การผสมคอลัมน์)

นำไบต์ 4 ตัวในแต่ละคอลัมน์มาคูณกันทางคณิตศาสตร์ เพื่อผสมข้อมูลในคอลัมน์นั้นเข้าด้วยกัน

คิดว่าเป็นการ "เขย่า" ข้อมูลในแนวตั้งของแต่ละคอลัมน์ ทำให้ไบต์แต่ละตัวมีอิทธิพลต่อไบต์อื่นในคอลัมน์เดียวกัน
ขั้นที่ 4

AddRoundKey
(การบวกกุญแจย่อย)

นำตารางข้อมูลไปผสม (XOR) กับ "กุญแจย่อยประจำรอบ" ที่คำนวณมาจากกุญแจหลัก

เป็นขั้นตอนเดียวที่ใช้กุญแจลับจริงๆ ส่วน 3 ขั้นตอนก่อนหน้าเป็นสูตรตายตัวที่ใครก็คำนวณตามได้

ตั้งค่าเริ่มต้น

ดูขั้นตอนการคำนวณทีละสเต็ป

ก่อนการคำนวณ
→
ผลลัพธ์หลังการคำนวณ
ยังไม่เริ่ม

กด "สร้างลำดับขั้นตอน" เพื่อเริ่มต้น

กรอกกุญแจและข้อมูลตั้งต้นด้านบน เลือกจำนวนรอบ (สูงสุด 3 รอบ) แล้วกดปุ่ม Next เพื่อดูการแปลงข้อมูลทีละขั้นตอน

คลิกไบต์ตำแหน่งไหนก็ได้ในตาราง 4×4 ทางซ้าย เพื่อดูว่าไบต์นั้นถูกแปลงด้วย S-box อย่างไรจริงๆ

ขั้นตอนที่ 0 / 0

ห้องทดลองดึงกุญแจ — AES แค่ 1 รอบ อ่อนแอแค่ไหน?

▶

เนื่องจาก K0 และ K1 เชื่อมกันด้วย Key Schedule ที่ตายตัว (K1 = KeySchedule(K0)) สมการการเข้ารหัสจึงมีตัวแปรเดียวคือ K0:

C = MixColumns(ShiftRows(SubBytes(P XOR K0))) XOR KeySchedule(K0)

ในห้องทดลองนี้ เราจำลองระบบที่ใช้ กุญแจ 16 บิต (2 ไบต์แรกของ K0 เท่านั้น ส่วนที่เหลือ 14 ไบต์กำหนดเป็น 0) — ทำให้มีความเป็นไปได้ทั้งหมด 216 = 65,536 ค่า ผู้โจมตีลองทุกค่าและเปรียบเทียบ C ที่ได้กับ C จริง

ทำไมกุญแจ 128 บิตจริงถึงแยกทีละไบต์ไม่ได้? MixColumns ผสมไบต์ข้ามตำแหน่งกัน ทำให้ K0 ทุกไบต์ส่งผลต่อ C พร้อมกัน จึงต้องลองทั้ง 2128 ≈ 3.4×1038 ค่า — เป็นไปไม่ได้ในทางปฏิบัติ

—
Ciphertext C (รู้)
—

??? (กำลังจะค้นหา)
ความคืบหน้า (0 – 65535)

ทำไม AES-128 จริงถึงปลอดภัย? กุญแจ 128 บิตทำให้ต้องลองถึง 2128 ≈ 3.4×1038 ค่า และแม้ว่าเราจะมีคอมพิวเตอร์เร็วที่สุดในโลก ก็ต้องใช้เวลานานกว่าอายุของจักรวาล นอกจากนี้ AES จริงยังมี 10-14 รอบ ทำให้ไม่มีโครงสร้าง algebraic ที่จะช่วยลดจำนวนการค้นหาได้

ทำไมเป้าหมายของการโจมตีคือ "กุญแจ" ไม่ใช่ "ข้อความ"

ในห้องทดลองด้านบน ผู้โจมตีเริ่มต้นรู้แค่ P กับ C ข้อความ P ที่ถอดออกมาได้ไม่มีประโยชน์อะไร เพราะรู้อยู่แล้วว่ามันคืออะไร สิ่งที่มีค่าคือ Master Key (K0) ที่กู้ออกมาได้จากการค้นหาแบบ byte-by-byte

เมื่อได้ K0 มาแล้ว ผู้โจมตีคำนวณ K1 = KeySchedule(K0) ได้ทันที จากนั้นสามารถถอด ciphertext ใหม่ C′ ที่ไม่เคยเห็นมาก่อนได้ทุกข้อความ: XOR กับ K1 → ผกผัน MixColumns → ผกผัน ShiftRows → ผกผัน SubBytes → XOR กับ K0

การโจมตีแบบนี้เรียกว่า key-recovery attack — ต่างจากการถอดได้แค่ข้อความเดียวตรงที่:

ถอดได้แค่ข้อความเดียว
กู้ Master Key ได้
ใช้ได้กับ C นั้นเท่านั้น
ถอดได้ทุก C ที่เข้ารหัสด้วยกุญแจนี้ ทั้งอดีตและอนาคต
ต้องโจมตีใหม่ทุกครั้ง
ทำครั้งเดียว ใช้ได้ตลอดอายุของกุญแจ
ไม่กระทบระบบอื่น
ถ้ากุญแจถูกใช้ซ้ำในหลายระบบ → กระทบหมดทุกระบบ

สรุป: 1 รอบอ่อนแอเพราะ SubBytes ทำทีละ 1 ไบต์ ทำให้แยกค้นหา 16 ไบต์อิสระกัน รวมเพียง 4,096 ครั้ง — ทำได้ในเสี้ยววินาที AES จริงปิดช่องโหว่นี้ด้วยการให้ MixColumns ผสมไบต์ข้ามกันก่อน SubBytes ในทุกรอบ จนไม่สามารถแยกค้นหาทีละไบต์ได้อีกต่อไป

การคำนวณทั้งหมด (S-box, MixColumns บน GF(2⁸), Rijndael key schedule) รันอยู่ในเบราว์เซอร์ของคุณเท่านั้น ไม่มีการส่งข้อมูลไปที่ไหน
